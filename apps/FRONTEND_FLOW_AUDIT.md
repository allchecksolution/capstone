# 프론트 흐름 대조 및 보완

이 문서는 제거된 웹뷰 구현의 과거 대조·검증 기록입니다. 현재 앱 소스와 실행 방법은 [Flutter 안내](flutter/README.md), 현재 연동 상태는 [ACK-22 인계 문서](flutter/ACK-22-HANDOFF.md)를 기준으로 확인하세요. 아래의 웹뷰 실행 결과는 Flutter 검증 결과가 아닙니다.

Figma 원본: https://www.figma.com/design/PfyqT7huiwtz63yKpfJzmA/

기존 화면을 삭제하는 의미로 ver2를 해석하지 않습니다. 동일한 목적의 흐름은 ver2를 우선하며 기존의 고유 기능은 유지합니다. 관리자 웹·모바일은 23:96 페이지, 기사는 0:1 페이지와 ver2 2235:973을 대조했습니다.

## 구현 및 검증 범위

- **업무 UI·로컬 동작**: 입력, 조회 조건, 상태 변경, 필수값 검증, 중복 처리 제한, 저장 실패 처리, 원본 및 수정 이력 보존 등은 프론트 상태로 구현했습니다.
- **공통 상태 미리보기**: Figma의 화면별 오류·제한·완료 상태를 목록화했습니다. 예외 화면은 공통 컴포넌트로 재현하며 업무 화면으로 돌아가거나 다음 처리 실패를 한 번 재현할 수 있습니다. 원본 스크린샷을 각각 그대로 복제한 것은 아닙니다.
- **연동 전**: 실제 인증, 사업자 조회, AI/STT, 푸시·배차 전달, 관리자·기사 간 실시간 데이터 교환, 동시 사용자 처리, 백그라운드 수집은 실제 서버/API 및 기기 검증이 필요합니다. 프론트의 성공 상태는 실제 발행·전송 완료를 의미하지 않습니다.

## 보완한 사항

### 관리자

- UC01: 기존 로그인/MFA와 오류를 유지하고 최초 인증 앱 등록 안내, 코드 만료·재입력을 추가했습니다. 실제 TOTP QR/시크릿은 발급하지 않습니다.
- UC02: 상담 목록·필터·검색, 분석자료 유무 구분, 녹음 자료가 있을 때만 재생 컨트롤 표시, 실패 접수 수동 입력, 최종 검토 및 필수값 보완을 추가했습니다.
- UC03/04: 검토 완료 접수만 의뢰로 등록, 중복 의뢰 방지, 후보 선별, 범위 확대, 기사 선택, 전달 성공/일부 실패/전체 실패 구분, 전달·배차 이력을 추가했습니다. 발행 접수를 실제 수신과 구분합니다.
- UC04/통계: 기존 기간/유형/상태/검색/CSV를 유지하고 담당 기사·지역 필터, 완료율·취소율·평균 비용·주별 분포, CSV/XLSX 형식 선택을 추가했습니다.
- UC05: 보고서 목록·미등록·수정·읽기 전용, 출장비/자재비/인건비 자동 합계, 최초 제출 원본·사진 불변, 작성자/시각/변경 전후의 누적 수정 이력을 추가했습니다.
- UC06: 기사 검색·계정 상태별 조회, 가입 정보 검토, 검증/누락 정보 확인, 승인 재확인·반려 사유·중복 심사 제한을 추가했습니다.
- UC07: 취소 요청 목록/사유, 이미 해제된 배정과 고객 의뢰 후속 처리를 구분하고 재배차/의뢰 취소의 중복·충돌 제한을 추가했습니다.
- UC16: 채팅방 검색, 메시지·실패·동일 메시지 재시도, 비활성/탈퇴 기사 과거 대화 읽기 전용을 추가했습니다.
- Softphone 폴더 권한 요청·저장·연결 해제 및 기존 계정/알림 설정은 유지합니다. 녹음 자동 가져오기는 별도 미구현입니다.

### 기사

- 기존 4단계 가입·승인 대기·반려·재신청, 대기/휴식, 배차·작업·사진 보고서·설정을 유지합니다.
- 기존의 Apple 로그인 선택지, 주소 입력 보완, 월별 상세 통계·분야별 분포·작업 내역, 로그아웃 확인을 복원했습니다. Apple 인증은 연결 준비 상태를 안내하며 실제 로그인으로 처리하지 않습니다.
- ver2의 배차 확정·거절·취소 접수·재방문·보고서 제출·탈퇴 완료 결과 화면을 연결했습니다.
- 비활성 계정 제한, 요청 만료, 사진/필수값 검증, 상태 순서/배정 제한, 보고서 중복 제출, 진행 작업 중 탈퇴 제한을 유지했습니다.
- 메시지 실패·재전송에서 동일 메시지 ID를 유지하고 알림센터 및 상태별 흐름 미리보기를 추가했습니다. 실제 푸시와 실시간 채팅은 연결 전입니다.

## 실제 검증

- 관리자 15개, 기사 9개 Node 검사 통과. 모델 불변 조건과 주요 화면 렌더링, 전체 Figma 카탈로그 도달 여부를 검사합니다.
- 에뮬레이터 실제 WebView: 관리자 접수 수동 보완→검토→의뢰→부분 전달 실패, 기사 승인, 보고서 수정/원본·이력, 재배차, 비활성 채팅 제한, 메시지 실패/재전송 및 모든 카탈로그 링크를 확인했습니다.
- 기사 실제 WebView: 배차 수락→결과→작업 완료→사진 보고서 제출→결과, 기존 상세 통계, 메시지 실패/재전송 및 모든 카탈로그 링크를 확인했습니다.
- 검증 중 기존 저장 데이터는 임시 보관 후 복원했습니다.
- 두 APK는 독립 패키지이며 서로 실시간으로 연결되지 않습니다. 이 검증은 실제 백엔드/AI 연동·동시성·실기기 백그라운드 동작을 검증하지 않습니다.
- 전체 화면에 대한 픽셀 단위 시각 일치 검증은 하지 않았습니다. Figma의 주요 레이아웃/아이콘을 유지하고 여러 오류 화면은 공통 상태 UI로 통합했습니다.

## 확인 방법

- 관리자: 더보기 → 예시 데이터 불러오기 → 각 업무 메뉴. 상태별 화면에서 Figma 항목 확인.
- 기사: 기사 화면 보기 → 홈의 예시 배차 → 더보기의 동작 흐름 미리보기. 최초 실행 데이터는 비어 있습니다.
- 키: 관리자 기존 의뢰 `allcheck-admin-prototype-v1`을 보존·이관하고 추가 업무 상태는 `allcheck-admin-operations-v2`; 기사는 기존 `allcheck-driver-ver2-v1` 유지.
- 파일·코드·APK만 갱신했습니다. 백엔드·AI 수정, 커밋·푸시, 외부 웹 재배포는 하지 않았습니다.
