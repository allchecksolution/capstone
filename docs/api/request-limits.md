# API 요청 제한

2026-11-18 사용자가 추천한 우선 적용안을 승인했다. 카카오 화면의 인증 실패 잠금은 요구사항에서 제외한 상태를 유지한다.

## 적용 범위

| 메서드·경로 | 사용자·집계 단위 | 허용 요청 수 |
|---|---|---|
| `POST /api/v1/auth/tokens/refresh` | 관리자·기사 모두, 계정별 모든 기기 합산 | 60초 동안 30회 |
| `POST /api/v1/drivers/me/registration` | 기사 계정별, 아래 재신청과 합산 | 60초 동안 5회 |
| `POST /api/v1/drivers/me/registration/resubmission` | 기사 계정별, 위 가입과 합산 | 같은 5회 한도 |

갱신과 가입의 카운터는 독립적이며 다른 계정의 횟수를 합산하지 않는다. 관리자 MASTER/SUB에도 같은 갱신 정책을 적용한다. 관리자·카카오 로그인, 로그아웃, 조회, 심사·탈퇴, 푸시 기기 API에는 이번 제한을 추가하지 않는다.

## 집계와 자동 해제

- 해당 계정·집계 단위의 첫 집계 요청부터 60초를 계산한다. 한도까지 허용하고 다음 요청부터 차단한다.
- 기존 구간의 종료 시각이 되면 자동 해제하며, 다음 요청부터 새로운 60초 구간과 횟수를 시작한다. 제한 중 재요청으로 종료 시각을 연장하지 않는다.
- 성공 요청, 이후 업무 검증·외부 호출·저장 실패가 발생한 요청, 동일 멱등성 키로 성공 결과를 다시 받는 요청도 집계한다. 업무 실패나 트랜잭션 롤백으로 횟수를 환불하지 않는다.
- 인증·인가 및 기본 입력 검증을 통과하여 애플리케이션 서비스에 도달한 요청을 집계한다. 가입·재신청은 국세청 호출과 업무 쓰기 트랜잭션 전에 확인한다.
- 갱신은 본문의 Refresh Token으로 활성 세션과 활성 계정을 확인한 뒤 집계한다. 계정 식별에 클라이언트 임의 계정 ID나 Bearer 헤더를 사용하지 않는다. 무효·이전·만료·폐기된 토큰은 기존 `REFRESH_TOKEN_INVALID`/401이며 계정 카운터를 새로 만들지 않는다. 비활성 계정은 기존 403이다.
- 갱신의 사전 식별 이후에도 회전·로그아웃·비활성화가 경합할 수 있으므로 실제 갱신 트랜잭션에서 계정 → 세션을 잠근 뒤 다시 검증한다. 이 단계의 실패도 이미 집계한 요청에 포함된다.

갱신 차단은 기존 Access Token·Refresh Token·세션·다른 기기를 폐기하지 않는다. 제한 중에도 현재 유효한 Access Token으로 조회하거나 로그아웃할 수 있다. 자동 해제 후 유효한 기존 Refresh Token으로 다시 갱신할 수 있다. 계정 비활성화·탈퇴·세션 만료와 같은 별도 차단 정책은 계속 적용한다.

## 차단 응답

HTTP 429, 공통 `ErrorResponse`를 사용한다.

```json
{"code":"TOO_MANY_REQUESTS","message":"요청이 많습니다. 안내된 시간 후 다시 시도해 주세요."}
```

- `Retry-After`: 구간 종료까지 남은 초를 올림한 양의 정수다. 초기 대기 시간은 최대 60초다.
- `Cache-Control: no-store`를 제공한다.
- 클라이언트는 남은 시간 후 재시도하며 429만으로 로그아웃하거나 즉시 자동 재시도하지 않는다.

프론트 공용 어댑터는 기존 `_refreshing` Future로 동시 갱신을 합치고 429 시 세션을 삭제하지 않는다. 새 REST 경로·DTO로 프론트 어댑터를 연결하는 전체 작업은 별도 후속 범위다.

## 저장과 운영

기존 PostgreSQL의 `request_limit_buckets`를 사용한다. 서버 메모리에 횟수를 저장하지 않고 DB 시간과 단일 UPSERT로 검사·집계하므로 여러 서버의 동시 요청과 재시작에도 한도를 공유한다. 업무 작업과 분리된 짧은 트랜잭션으로 카운터를 커밋한 뒤 외부 API 호출이나 업무 트랜잭션을 실행한다.

V7 마이그레이션과 기술용 JPA 매핑을 추가하며 기존 적용 마이그레이션을 변경하지 않는다. 계정·집계 단위별 한 행을 재사용하고, 만료는 행 삭제 없이 다음 요청에서 초기화한다. 자동 삭제 주기는 추가하지 않았으며 개인정보 보존·삭제 정책은 별도 결정 사항이다. 토큰·비밀번호·요청 본문·국세청 정보는 카운터에 저장하지 않는다.

DB 장애는 공통 서버 오류로 처리하며 요청을 무제한 통과시키는 대체 경로를 두지 않는다. 로그인 전 요청 폭주 방어, IP 기준 제한, 푸시 기기 제한은 이번 구현에 포함하지 않는다. 실제 HTTP 및 DB 동시성·롤백·만료 검증 결과는 [인수인계](identity-handoff.md#검증-및-환경)에 기록한다.
