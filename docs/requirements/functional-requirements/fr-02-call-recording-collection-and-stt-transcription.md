# FR-02 상담 녹음 자동 수집 및 STT 변환

| 항목            | 내용                                                                                                                                                                                                                                                                                                          |
|---------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **요구사항 유형**   | 시스템                                                                                                                                                                                                                                                                                                         |
| **요구사항 명칭**   | 상담 녹음 자동 수집 및 STT 변환                                                                                                                                                                                                                                                                                        |
| **정의**        | 고객과 관리자의 전화 상담 종료 후 생성된 녹음 파일을 시스템이 자동으로 확보하고 STT를 통해 텍스트로 변환해야 한다.                                                                                                                                                                                                                                         |
| **세부 내용**     | 1. 전화 상담 종료 후 생성된 녹음 파일을 자동으로 확보할 수 있어야 한다.<br>2. 확보한 녹음 파일을 상담 건과 연결하여 저장할 수 있어야 한다.<br>3. 시스템은 녹음 파일을 STT 서비스에 전달하여 상담 내용을 텍스트로 변환해야 한다.<br>4. STT 변환 결과를 원본 녹음 파일과 함께 저장해야 한다.<br>5. 녹음 파일 확보 또는 STT 처리에 실패한 경우 실패 상태를 기록하고 관리자가 확인할 수 있어야 한다.<br>6. 녹음 파일 자동 수집 또는 STT 처리가 불가능한 경우, 관리자가 상담 접수 정보를 직접 입력할 수 있는 수단을 제공해야 한다. |
| **설계 시 고려사항** | 관리자 앱이 녹음을 S3에 업로드하고 완료를 알리면 Backend가 검증 후 최초 분석을 자동 시작한다.<br>녹음 원본은 비공개 S3에, STT 원문은 DB에 보관한다. Backend가 접수 연결·처리 상태와 원문을 관리하며 원문 저장 후 구조화를 요청한다.<br>MVP는 접수당 녹음 1개이며 완료 전 업로드 재시도는 지원하고 원본 교체는 제외한다.<br>모바일의 실제 녹음 확보·자동 수집 가능 여부 및 수동 파일 선택 UI는 프런트 PoC로 검증한다. 수동 접수 정보 입력과 구분한다. |
| **관련 유스케이스**  | [UC-02 AI 분석 결과 검토 및 수정](../use-cases/uc-02-ai-reception-review.md)의 선행 시스템 기능                                                                                                                                                                                                                              |

상세 업무 정책은 [BR-09](../../../apps/backend/docs/business-specification.md#br-09), 요청·응답은 [Backend OpenAPI](../../api/openapi.yaml)를 따른다.

STT 응답의 `transcript`를 변경 없이 DB에 저장한 뒤 같은 문자열을 구조화 요청의 `transcript`로 전달한다.
관리자 상세 조회에는 DB 원문을 제공하고 STT용 S3 파일 접근 URL은 발급하지 않는다.
STT 결과가 비어 있거나 공백뿐이면 '전사 내용 없음' 실패로 기록하고 원문 저장·구조화 호출을 진행하지 않는다.
녹음 원본 조회와 관리자 수동 보완·검토 완료는 계속 지원한다. 실패 알림은 BR-09의 발행 절차를 따른다.

녹음 업로드 형식은 WAV로 확정한다. 확장자와 WAV MIME을 검사하고, 완료 확인 때 실제 S3 객체의 WAVE 헤더·크기·SHA256을 검증한다.
앱은 원본 제목을 `originalFilename`에 담는다. Backend는 알려진 파일명 규칙의 두 전화번호가 동일할 때 검토용 연락처를 자동 채운다.
번호가 다르거나 파일명 규칙을 확인할 수 없으면 임의로 선택하지 않고 관리자 보완으로 진행한다. 파일명 시각으로 분석 기준 시각을 변경하지 않는다.
업로드 재요청은 파일 예약을 중복 생성하지 않으며 URL만 새로 발급한다. 서명 URL은 DB에 보관하지 않는다.
최대 파일 크기·녹음 길이·세부 코덱 제한은 확정 전이며 예시 값으로 제한하지 않는다.
