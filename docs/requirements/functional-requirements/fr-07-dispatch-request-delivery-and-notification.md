# FR-07 배차 요청 및 알림

| 항목            | 내용                                                                                                                                                                                                                                                      |
|---------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **요구사항 유형**   | 시스템 / 기사                                                                                                                                                                                                                                                |
| **요구사항 명칭**   | 배차 요청 전달 및 알림                                                                                                                                                                                                                                           |
| **정의**        | 시스템은 배차 후보로 선정된 기사에게 신규 배차 요청을 전달하고 기사가 이를 확인할 수 있도록 해야 한다.                                                                                                                                                                                             |
| **세부 내용**     | 1. 시스템은 선별된 기사에게 배차 요청을 생성해야 한다.<br>2. 기사에게 신규 배차 요청 발생 사실을 Push Notification으로 전달해야 한다.<br>3. 기사는 자신에게 전달된 요청을 확인할 수 있어야 한다.<br>4. 기사는 작업 유형, 증상, 작업 위치 및 방문 관련 정보 등 배차 판단에 필요한 정보를 확인할 수 있어야 한다.<br>5. 이미 종료되거나 다른 기사에게 배정된 요청은 유효하지 않은 요청으로 처리해야 한다. |
| **설계 시 고려사항** | FCM 기반 Push Notification 활용<br>Push Notification 자체가 의뢰 데이터의 원본이 되지 않도록 하고 앱에서 서버의 최신 배차정보 조회                                                                                                                                                           |
| **관련 유스케이스**  | [UC-03 의뢰 등록](../use-cases/uc-03-dispatch-request.md), [UC-10 배차 요청 수락 및 거절](../use-cases/uc-10-dispatch-request-response.md)                                                                                                                           |

정확한 방문 시작·종료 시각과 선택적인 고객 부가정보 `notes`는 관리자 검토 후 의뢰에 보존된 값을 사용한다.
본인에게 배차 요청이 전달된 후보 기사부터 조회할 수 있고, 수락 후 담당 기사도 계속 조회할 수 있다.
접수 원본에 대한 관리자 소유권과 기사 배차 요청·작업 조회 권한은
[BR-02](../../../apps/backend/docs/business-specification.md#br-02), 접수 스냅샷의 기준은
[BR-04](../../../apps/backend/docs/business-specification.md#br-04)를 따른다.
고객 연락처는 수락 후 해당 의뢰의 담당 기사에게만 제공한다. 배차 후보에게는 연락처를 제공하지 않으며, notes의 후보 공개 정책과 구분한다.

수락 전 배차 요청의 주소는 시·군·구와 읍·면·동 수준까지만 제공하고 현장까지의 직선거리를 함께 표시한다. 도로명·건물번호·동호수와 현장 좌표는 배차 요청 응답에 포함하지 않으며, 전체 확정 주소는 수락 후 권한 있는 작업 조회에서 제공한다. 작업 유형·증상·방문 시간·검토된 부가정보의 기존 공개 기준은 유지하며 상세 기준은 [BR-02](../../../apps/backend/docs/business-specification.md#br-02)를 따른다.

배차 알림은 해당 기사의 등록된 활성 기기 전체에 전송하되, 기사당 하나의 배차 요청과 응답 기한을 공유한다. 어느 기기에서든 먼저 확정된 유효 응답을 해당 기사의 응답으로 처리한다. 기기별 전송 결과와 기사 단위 전달 상태의 집계는 [BR-01](../../../apps/backend/docs/business-specification.md#br-01) 및 [BR-04](../../../apps/backend/docs/business-specification.md#br-04)를 따르며, 기기 등록·토큰 관리는 타 도메인 연동으로 분리한다.
