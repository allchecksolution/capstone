# FR-09 의뢰 및 작업 진행 상태 관리

| 항목            | 내용                                                                                                                                                                                                                                                                                                                                                            |
|---------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **요구사항 유형**   | 관리자 / 기사                                                                                                                                                                                                                                                                                                                                                      |
| **요구사항 명칭**   | 의뢰 및 작업 진행 상태 관리                                                                                                                                                                                                                                                                                                                                              |
| **정의**        | 관리자와 기사가 의뢰의 배차 및 작업 진행 상태를 확인하고, 기사가 작업 진행 상황에 따라 상태를 변경할 수 있어야 한다.                                                                                                                                                                                                                                                                                          |
| **세부 내용**     | 1. 관리자는 작업 현황 및 통계 화면에서 등록된 의뢰 및 작업 목록과 현재 진행 상태를 조회할 수 있어야 한다. 조회할 데이터가 없는 경우에도 화면에 접근할 수 있어야 한다. 진행 중인 작업과 과거 완료·취소된 작업의 조건별 조회 및 기간별 통계는 [FR-16](./fr-16-work-history-and-statistics-management.md)을 따른다.<br>2. 관리자는 현재 배차 상태와 담당 기사를 확인하고, [FR-16](./fr-16-work-history-and-statistics-management.md)에 따라 최초 배차 및 재배차 이력을 현재 배차 정보와 구분하여 조회할 수 있어야 한다.<br>3. 기사는 자신에게 유효하게 배정된 의뢰의 작업 상태를 변경할 수 있어야 한다. [FR-12](./fr-12-dispatch-cancellation-and-redispatch-management.md)에 따라 배차 취소 요청이 정상 접수되면 기존 배정이 즉시 해제되어 해당 의뢰의 작업 상태 변경 권한이 종료되고, 다른 배차 요청을 수락할 수 있어야 한다. 기사 배정 해제는 고객 의뢰 자체의 취소를 의미하지 않으며 관리자 후속 처리가 필요하다.<br>4. 시스템은 작업 시작·완료 등의 상태 변경을 저장해야 한다.<br>5. 기사에 의해 변경된 작업 상태를 관리자 화면에도 반영해야 한다.<br>6. 시스템은 작업 상태 변경 시 현재 상태와 변경하려는 상태를 기준으로 허용된 상태 전이인지 검증해야 하며, 허용되지 않은 상태 변경을 거부해야 한다.<br>7. 작업이 완료되지 않고 추가 방문이 필요한 경우 재방문 상태를 관리할 수 있어야 한다.<br>8. [UC-03](../use-cases/uc-03-dispatch-request.md)의 후보 미확보 및 전체 전달 실패를 정상적인 배차 진행과 구분하여 관리·안내해야 한다. 일부 전달 실패는 기사별 전달 결과를 기록하고 정상 전달된 기사에 대한 배차 절차를 유지하며, 일부 실패만으로 의뢰 전체를 배차 실패 처리하지 않아야 한다. 푸시 발행 또는 전달 서비스의 접수 성공을 기사의 실제 수신·확인 성공과 동일하게 취급하지 않아야 한다. |
| **설계 시 고려사항** | 기사 배정 상태, 취소 요청 처리 상태, 고객 의뢰 상태 및 작업 상태의 구분과 상태 전이 정의<br>상태 변경 시각 및 변경 이력 저장<br>실시간 상태 반영 방식 적용<br>후보 미확보·전체 전달 실패·일부 전달 실패 및 취소·재배차 흐름의 구체적인 상태 명칭과 상세 전이, 재시도 정책은 추후 설계한다. 구체적인 상태 전이 규칙과 예외적인 상태 보정 정책은 작업 진행 및 취소·재배차 흐름을 고려하여 정의한다. [UC-11](../use-cases/uc-11-work-status-update.md) 및 [FR-12](./fr-12-dispatch-cancellation-and-redispatch-management.md)과 상태 명칭 및 처리 기준을 일치시킨다.                                                                            |
