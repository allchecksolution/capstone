# FR-11 작업 보고서 등록 및 관리

| 항목            | 내용                                                                                                                                                                                                                                                                                            |
|---------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **요구사항 유형**   | 기사 / 관리자                                                                                                                                                                                                                                                                                      |
| **요구사항 명칭**   | 작업 보고서 등록 및 관리                                                                                                                                                                                                                                                                                |
| **정의**        | 기사가 수행한 작업의 내용과 결과를 보고서로 등록하고 관리자가 이를 조회 및 관리할 수 있어야 한다.                                                                                                                                                                                                                                      |
| **세부 내용**     | 1. 기사는 자신에게 배정된 작업에 대한 보고서를 작성할 수 있어야 한다.<br>2. 작업 전·후 사진을 등록할 수 있어야 한다.<br>3. 작업 내용, 진단 결과, 작업 비용 등의 정보를 입력할 수 있어야 한다.<br>4. 시스템은 보고서를 해당 의뢰 및 담당 기사와 연결하여 저장해야 한다.<br>5. 관리자는 기사가 제출한 작업 보고서를 조회할 수 있어야 한다.<br>6. 관리자는 권한이 허용된 보고서 정보를 수정할 수 있어야 한다.<br>7. 시스템은 기사가 최초 제출한 작업 보고서 원본(작업 전·후 사진 포함)을 보존하고 관리자 수정으로 덮어쓰지 않아야 한다. 관리자 수정 내용은 원본과 별도의 수정 이력으로 누적 관리하며, 수정 항목, 수정 전 값, 수정 후 값, 수정자, 수정 시각을 기록해야 한다.<br>8. 작업 이력 조회 및 통계에는 최신 유효 수정 내용을 반영하고, 수정 내용이 없으면 제출 원본을 사용해야 한다. 원본과 전체 수정 이력은 추적할 수 있어야 하며, 보고서 수정에는 별도의 승인 절차를 두지 않는다.<br>9. 기사 탈퇴 시 보고서 원본·수정 이력·첨부 파일에도 [UC-16](../use-cases/uc-16-driver-account-withdrawal.md)의 접근 통제 및 개인정보 보존·파기 정책을 적용한다.<br>10. 동일 작업의 최초 보고서 제출 요청이 반복되더라도 보고서를 중복 생성하지 않고 기존 제출 결과를 반환하거나 중복 제출임을 안내해야 한다. 중복 제출로 작업 이력이 중복 생성되거나 작업 완료 통계가 중복 집계되지 않아야 한다. 정상적인 보고서 수정은 새로운 최초 제출로 처리하지 않으며, 수정 이력 생성과 작업 이력·통계의 중복 생성을 구분해야 한다. |
| **설계 시 고려사항** | 이미지 파일 저장소와 DB 메타데이터 분리 고려<br>작업 보고서 원본·수정 이력 분리 저장 및 최신 유효 수정 내용의 조회·집계 반영<br>구체적인 보존 기간과 파기 방법은 관련 법령 및 개인정보 처리 정책을 검토하여 결정 |
