# FR-04 AI 분석 결과 검토 및 수정

| 항목            | 내용                                                                                                                                                                                                                                                                            |
|---------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **요구사항 유형**   | 관리자                                                                                                                                                                                                                                                                           |
| **요구사항 명칭**   | AI 분석 결과 검토 및 수정                                                                                                                                                                                                                                                              |
| **정의**        | 관리자가 상담 녹음, STT 결과 및 AI가 추출한 접수 정보를 비교하고 잘못된 정보를 수정하여 최종 접수 정보를 확정할 수 있어야 한다.                                                                                                                                                                                                 |
| **세부 내용**     | 1. 관리자는 상담 녹음 원본이 존재하는 경우 이를 확인할 수 있어야 한다.<br>2. 관리자는 STT 결과가 존재하는 경우 변환된 상담 내용을 확인할 수 있어야 한다.<br>3. 관리자는 AI 분석 결과가 존재하는 경우 추출된 작업 유형, 증상, 주소, 방문 희망시간 등의 정보를 확인할 수 있어야 한다.<br>4. 잘못 추출되거나 누락된 정보를 관리자가 수정할 수 있어야 한다.<br>5. 관리자는 검토한 접수 정보를 최종 확정할 수 있어야 한다.<br>6. 시스템은 관리자가 최종 확정한 정보를 의뢰 등록에 사용할 수 있도록 저장해야 한다.<br>7. 녹음 수집·STT·AI 분석 실패 시에도 관리자가 접수 정보를 수동 입력하고 동일한 검토 완료 및 최종 확정 저장 절차를 진행할 수 있어야 한다. |
| **설계 시 고려사항** | AI 원본 분석 결과와 관리자 수정 결과를 구분하여 관리하는 방안 고려<br>필수 접수정보에 대한 입력값 검증 적용                                                                                                                                                                                                              |
| **관련 유스케이스**  | [UC-02 AI 분석 결과 검토 및 수정](../use-cases/uc-02-ai-reception-review.md)                                                                                                                                                                                                           |

최초 AI 결과로 편집값을 자동 채우는 조건, 확정 필수값(작업 유형·증상·주소·정확한 방문 시작/종료 시각·연락처),
의뢰 등록 전 확정 취소 후 수정 및 의뢰 등록 후 접수 수정 금지 정책은
[BR-04](../../../apps/backend/docs/business-specification.md#br-04)를 따른다.
고객명은 확정 필수항목에 포함하지 않는다. 연락처 자동 확보 여부와 관계없이 관리자가 보완할 수 있어야 한다.
원본 녹음 파일명에서 확보한 연락처는 검토 입력값에 자동으로 제공하며 AI 원본과 구분한다.
이 연락처가 있다고 다른 필드의 AI 자동 채움을 생략하지 않는다. 분석 실패 후에도 확보한 번호는 유지하며 관리자가 확인·수정한 번호를 우선한다.

본인이 생성한 접수에 대한 조회·수정·검토 확정·확정 취소 권한은 [BR-02](../../../apps/backend/docs/business-specification.md#br-02)를 따른다.
고객의 부가 요청·전달사항은 선택 항목 `notes`로 검토·수정할 수 있고, 의뢰에 함께 보존하여 기사에게 전달한다.
방문 시각은 정확한 시작·종료 시각으로만 취급하며 별도 방문 텍스트 필드는 제공하지 않는다.
AI가 정확한 시각을 추출하지 못하면 관리자가 시각을 보완해야 확정·의뢰 등록할 수 있다.
AI 원본 JSON은 관리자가 수정한 최종 방문 시각과 구분하여 보존한다.
부가정보는 본인에게 배차 요청이 전달된 후보 기사부터 조회할 수 있고, 수락 후 담당 기사도 계속 조회할 수 있다.
관리자 상세 조회 API는 STT 원문, 녹음 원본 접근 수단, 수정되지 않은 AI 원본 JSON 필드와 관리자 편집값을 구분하여 제공해야 한다.
관리자는 분석 결과 검토 시 `notes`도 다른 접수 필드와 동일하게 확인·추가·수정할 수 있어야 한다.
관리자가 수정한 `finalData.notes`와 AI가 추출한 `aiOriginal.notes`를 구분하여 제공한다.
MVP에서는 AI 원본과 최신 관리자 편집값만 보관하며, 매 저장 시 변경 전후 값의 수정 이력은 추가하지 않는다.
관리자 임시 저장 기능은 제공하지 않는다. 화면에서 수정한 전체 최종값을 검토 완료 요청에 담고,
필수값·정확한 방문 구간·소유권·버전을 검증한 뒤 수정값 저장과 검토 확정을 함께 처리한다.
필수값을 지우거나 누락한 요청은 거부하며, 실패 시 이전 값과 상태를 유지한다.
검토 완료 시 방문 종료 시각은 서버 현재 시각보다 뒤여야 한다. 시작 시각이 지났어도 종료가 미래인 진행 중 구간은 허용한다.
종료가 현재와 같거나 과거이면 저장·확정하지 않는다. 이 규칙으로 과거 접수의 조회를 제한하지 않는다.
미래 종료 여부는 검토 완료 때만 검사한다. 이후 의뢰 등록에서는 종료가 지났더라도 이 조건을 재검사하지 않는다.
AI 분석 진행 중에는 결과 화면을 읽기 전용으로 두며 입력·수정·검토 완료를 허용하지 않는다.
서버도 진행 중 검토 완료를 거부한다. 분석 성공 후 결과를 확인·수정하고, 실패가 확정된 경우에는 수동 보완 후 검토 완료한다.
