# FR-01 관리자 로그인

| 항목 | 내용 |
|---|---|
| **요구사항 유형** | 관리자 |
| **요구사항 명칭** | 관리자 로그인 |
| **정의** | 사전에 등록된 관리자만 ID/PW 인증을 통해 관리자 시스템에 접근할 수 있어야 한다. |
| **세부 내용** | 1. 공개적인 관리자 회원가입 기능은 제공하지 않는다.<br>2. 관리자 계정은 마스터 관리자와 부 관리자로 구분되며(`role`), 사전에 등록된 ID/PW로 인증한다.<br>3. ID/PW 인증 성공 시 서비스 Access Token과 Refresh Token을 발급한다.<br>4. MFA 추가 인증 및 최초 TOTP 등록·검증은 구현하지 않는다.<br>5. 로그인 실패 시 관리자에게 인증 실패 결과를 제공하되 아이디와 비밀번호 중 어느 항목이 일치하지 않는지 구분하여 노출하지 않는다. |
| **설계 시 고려사항** | Spring Security 기반 인증·인가 적용<br>Access Token 기반 API 인증<br>Refresh Token 관리 및 폐기 정책 적용<br>비밀번호는 안전한 단방향 해시로 저장<br>**(확정)** 마스터/부 관리자(`MASTER`/`SUB`)는 동일한 업무 권한을 가진다. 역할 값은 구분하여 보존하고 리소스별 접근·업무 상태·이력 보존 규칙은 두 역할에 동일하게 적용한다. |
| **관련 유스케이스** | [UC-01 관리자 로그인](../use-cases/uc-01-admin-login.md) |

## 관리자 계정 관리 정책 (2026-11-24)

- 개발자·운영자가 CLI로 최초 관리자를 한 번 발급하고 실제 관리자는 앱의 ID/PW 화면으로 로그인한다.
- 최초 관리자만 추가 관리자 생성, 로그인 ID 변경, 비밀번호 재설정, 비활성화를 수행한다. 추가 관리자는 다른 관리자를 생성하거나 관리할 수 없다.
- 최초 관리자는 본인 탈퇴·비활성화가 불가능하다. 다른 관리자도 최초 계정을 변경·삭제할 수 없다.
- 관리자 간 업무 권한은 동일하며 계정 관리 권한은 최초 계정 여부로 구분한다.
- 초기 비밀번호의 첫 로그인 변경을 강제하지 않는다. 본인 비밀번호 변경은 모든 관리자에게 허용한다.
- 삭제는 이력을 보존하는 비활성화이며, 자격 증명 변경·비활성화 시 기존 모든 세션을 폐기한다.
- 최초 관리자 비밀번호 분실은 운영자 전용 CLI로 복구한다.
- 구현·운영 상세: [관리자 계정 운영](../../../apps/backend/docs/administrator-accounts.md).
