# FR-12 배차 취소 및 재배차 관리

| 항목            | 내용                                                                                                                                                                                                                                                                 |
|---------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **요구사항 유형**   | 기사 / 관리자 / 시스템                                                                                                                                                                                                                                                     |
| **요구사항 명칭**   | 배차 취소 및 재배차 처리                                                                                                                                                                                                                                                     |
| **정의**        | 담당 기사가 작업 수행이 어려운 경우 배차 취소를 요청할 수 있으며 시스템과 관리자는 해당 의뢰의 후속 배차를 처리할 수 있어야 한다.                                                                                                                                                                                        |
| **세부 내용**     | 1. 담당 기사는 배차 취소를 요청할 수 있어야 한다.<br>2. 기사는 배차 취소 사유를 입력할 수 있어야 한다.<br>3. 시스템은 취소 요청과 사유를 관리자 검토 대기 상태로 기록해야 한다. 이는 취소 요청의 처리 상태이며 의뢰 자체의 상태가 아니다. 취소 요청만으로 기존 배차를 즉시 취소하지 않고 관리자 결정 전까지 기존 배차 관계를 유지해야 한다.<br>4. 관리자에게 배차 취소 상황을 제공해야 한다.<br>5. 관리자가 재배차 또는 의뢰 취소를 결정한 뒤 해당 결정에 따라 실제 배차·의뢰 상태를 변경해야 한다.<br>6. 관리자는 취소 요청을 검토하여 재배차를 진행하거나 의뢰 자체를 취소할 수 있어야 한다.<br>7. 재배차 시 기존 배차 및 취소 이력을 유지해야 한다.<br>8. 시스템은 동일한 취소 요청의 중복 처리를 방지하고 관리자 처리 시점의 배차 상태를 확인해야 한다. |
| **설계 시 고려사항** | 배차 이력을 덮어쓰지 않고 별도의 이력으로 관리<br>취소 이후 후보 재선정 및 관리자 개입 정책 정의<br>관리자 검토 중 기사의 작업 진행 가능 여부, 작업 상태 변경 제한 및 상세 상태 전이 규칙은 추후 결정한다. |
