# FR-12 배차 취소 및 재배차 관리

| 항목            | 내용                                                                                                                                                                                                                                                                 |
|---------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **요구사항 유형**   | 기사 / 관리자 / 시스템                                                                                                                                                                                                                                                     |
| **요구사항 명칭**   | 배차 취소 및 재배차 처리                                                                                                                                                                                                                                                     |
| **정의**        | 담당 기사가 작업 수행이 어려운 경우 배차 취소를 요청할 수 있으며 시스템과 관리자는 해당 의뢰의 후속 배차를 처리할 수 있어야 한다.                                                                                                                                                                                        |
| **세부 내용**     | 1. 담당 기사는 배차 취소를 요청할 수 있어야 한다.<br>2. 기사는 배차 취소 사유를 입력할 수 있어야 한다.<br>3. 시스템은 유효한 배정 여부와 취소 요청이 허용되는 상태인지 확인하고, 유효한 요청이면 취소 요청 접수와 기존 배정 해제를 원자적으로 처리해야 한다. 정상 접수 즉시 기사의 기존 배정은 종료되며, 취소 요청과 사유는 관리자 후속 처리를 기다리는 것으로 기록해야 한다. 취소 요청의 처리 상태와 의뢰 자체의 상태는 구분해야 한다.<br>4. 관리자에게 배차 취소 상황을 제공해야 한다.<br>5. 배정에서 해제된 기사는 해당 의뢰의 작업 상태를 변경할 수 없으며 다른 배차 요청을 수락할 수 있어야 한다. 배정 해제만으로 고객 의뢰 자체가 취소되지는 않아야 한다.<br>6. 관리자는 남아 있는 고객 의뢰에 대해 재배차 또는 의뢰 자체 취소를 결정할 수 있어야 한다. 시스템은 최신 의뢰 상태 및 배차 상태를 확인하고, 여러 관리자가 동시에 처리하더라도 두 결정 중 하나만 확정되도록 관리자 처리를 원자적으로 수행해야 한다. 이미 처리되었거나 다른 관리자가 처리 중인 요청은 중복 처리하지 않고, 중복·충돌 시 현재 처리 상태를 안내해야 한다.<br>7. 기존 배차 및 취소 이력을 보존해야 한다.<br>8. 시스템은 동시 요청에도 동일 배정의 취소 접수와 배정 해제가 한 번만 성공하도록 보장해야 한다. 이미 정상 처리된 요청은 취소 요청·관리자 후속 처리 요청을 중복 생성하거나 배정 해제를 반복하지 않고 기존 처리 결과를 반환하거나 중복 요청임을 안내해야 한다. |
| **설계 시 고려사항** | 배차 이력을 덮어쓰지 않고 별도의 이력으로 관리<br>취소 이후 후보 재선정 및 관리자 개입 정책 정의<br>중복 요청 식별 방식, 취소 접수·배정 해제 및 관리자 후속 처리의 원자성 보장 방식과 충돌 해결 구현은 추후 설계한다.<br>취소가 허용되는 구체적인 작업 상태, 상세 상태 명칭 및 상태 전이 규칙은 추후 결정한다. |
