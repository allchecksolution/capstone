# UC-01 관리자 로그인

| 항목 | 내용 |
|---|---|
| **행위자** | 관리자 |
| **유스케이스 내용** | 사전에 등록된 관리자 계정의 ID/PW로 로그인하여 관리자 시스템에 접근한다. |
| **사전 조건** | 관리자 계정이 사전에 시스템에 등록되어 있어야 한다. 마스터 관리자 또는 부 관리자는 `role`로 구분한다. |
| **기본 흐름** | 1. 관리자가 아이디와 비밀번호를 입력한다.<br>2. 시스템이 입력된 계정 정보를 확인한다.<br>3. 인증에 성공하면 서비스 Access Token과 Refresh Token을 발급하고 관리자 로그인을 완료한다. |
| **예외 흐름** | E1. 아이디 또는 비밀번호가 일치하지 않는 경우 → 시스템이 로그인 실패를 안내하되 어느 항목이 일치하지 않는지 구분하여 노출하지 않는다. |
| **대안 흐름** | 없음. 최초 로그인도 동일한 ID/PW 인증을 사용하며 MFA 및 TOTP 등록·검증은 진행하지 않는다. |
| **사후 조건** | 관리자가 인증된 상태가 된다. 실제 기능 접근에는 관리자 유형·리소스별 권한 검사를 적용한다. 마스터/부 관리자는 같은 인증 절차와 동일한 업무 권한을 가진다. 역할(`role`) 값은 구분하여 보존하며 업무 상태·이력 보존 규칙도 동일하게 적용한다. |

## 계정 발급 및 복구 흐름 (2026-11-24)

1. 운영자가 CLI로 최초 관리자를 발급하거나 기존 활성 계정을 명시적으로 지정한다.
2. 최초 관리자는 일반 ID/PW 화면으로 로그인하며 첫 비밀번호 변경은 강제되지 않는다.
3. 최초 관리자는 로그인 후 계정 관리에서 추가 관리자를 생성·수정·비활성화한다.
4. 추가 관리자는 같은 로그인 화면과 업무 기능을 사용하지만 계정 관리 기능은 사용할 수 없다.
5. 비밀번호 분실 시 최초 관리자는 운영자에게 복구를 요청하고 운영자는 CLI로 비밀번호 재설정과 기존 세션 폐기를 수행한다.
6. 최초 관리자 본인 탈퇴는 거절하며 추가 계정 삭제는 이력을 보존하는 비활성화로 처리한다.
