# UC-12 작업 보고서 등록

| 항목           | 내용                                                                                                                                                                                                                                  |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 기사                                                                                                                                                                                                                                  |
| **유스케이스 내용** | 기사가 수행한 작업의 내용과 결과를 작업 보고서로 등록한다.                                                                                                                                                                                                   |
| **사전 조건**    | 1. 기사가 로그인되어 있어야 한다.<br>2. 해당 기사가 작업의 유효한 담당자여야 하며, 작업이 보고서 제출이 허용되는 상태여야 한다. |
| **기본 흐름**    | 1. 기사가 작업 보고서 작성 화면에 진입한다.<br>2. 기사가 작업 전·후 사진을 등록한다.<br>3. 기사가 작업 내용, 진단 결과, 작업 비용 등 필요한 정보를 입력한다.<br>4. 기사가 작업 보고서를 제출한다.<br>5. 시스템이 입력된 정보와 제출 시점의 유효 담당자·작업 상태·제출 권한을 확인한다.<br>6. 시스템이 동일 작업의 최초 제출 요청의 반복 여부를 확인하여 보고서를 중복 생성하지 않고 해당 의뢰에 연결하여 저장한다.<br>7. 등록된 작업 보고서를 관리자가 조회할 수 있는 상태로 변경한다. |
| **예외 흐름**    | E1. 필수 항목이 누락된 경우 → 시스템이 누락된 정보를 안내한다.<br>E2. 사진 등록에 실패한 경우 → 시스템이 재등록을 요청한다.<br>E3. 보고서 저장에 실패한 경우 → 시스템이 오류를 안내한다.<br>E4. 작업이 취소되었거나 다른 기사에게 재배차되어 제출 권한이 없거나, 보고서 제출이 허용되지 않는 작업 상태인 경우 → 시스템이 제출을 거부하고 사유를 안내한다.<br>E5. 이미 정상 처리된 동일한 최초 제출 요청이 반복된 경우 → 시스템이 기존 제출 결과를 반환하거나 중복 제출임을 안내하고 새로운 보고서를 생성하지 않는다. |
| **대안 흐름**    | A1. 임시 저장 기능을 제공하는 경우 → 기사가 작성 중인 보고서를 임시 저장하고 이후 작성을 계속한다.<br>A2. 최초 제출 이후 정상적으로 보고서를 수정하는 경우 → [FR-11](../functional-requirements/fr-11-work-report-registration-and-management.md) 및 [UC-05](./uc-05-work-report-review.md)에 따른 관리자 수정으로 처리하며, 새로운 최초 보고서 제출로 처리하지 않는다.                                                                                                                                                                         |
| **사후 조건**    | 작업 보고서가 해당 의뢰 및 작업 이력에 저장되고 관리자가 조회할 수 있다.<br>최초 제출 원본(작업 전·후 사진 포함)은 [FR-11](../functional-requirements/fr-11-work-report-registration-and-management.md)에 따라 보존하고 관리자 수정은 수정 전후 내용, 수정자, 수정 시각을 포함한 별도 이력으로 기록한다. 별도의 승인·반려 절차 없이 작업 이력 및 통계에는 최신 유효 수정 내용을 반영한다. 중복 제출로 작업 이력이나 작업 완료 통계가 중복 생성·집계되지 않아야 하며, 보고서 수정 이력의 생성과 작업 이력·통계의 중복 생성을 구분한다. 원본·수정 이력·첨부 파일의 접근 통제 및 보존·파기는 [UC-15](./uc-15-driver-account-withdrawal.md)을 따른다. |
| **설계 시 고려사항** | 정확한 보고서 제출 가능 상태, 임시 저장 제공 여부 및 재제출 정책은 추후 결정하되, 동일한 최초 제출 요청으로 보고서가 중복 생성되지 않아야 한다. 중복 요청 식별 방식, 멱등성 키의 생성 방식·유일성 범위·보존 기간 및 반복 요청에 대한 구체적인 HTTP 응답·오류 코드는 추후 설계한다. |
