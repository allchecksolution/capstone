# UC-02 AI 접수 정보 검토 및 수정

| 항목           | 내용                                                                                                                                                                                                             |
|--------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 관리자                                                                                                                                                                                                            |
| **유스케이스 내용** | 전화 상담 내용을 기반으로 AI가 추출한 주요 접수 정보를 관리자가 확인하고 필요한 경우 수정한다.                                                                                                                                                        |
| **사전 조건**    | 1. 관리자가 로그인되어 있어야 한다.<br>2. 해당 관리자가 생성한 상담 접수가 등록되어 있어야 한다.<br>3. 분석 진행 중이거나 결과 또는 녹음 수집·STT·원문 저장·AI 처리 실패 상태를 조회할 수 있어야 한다. |
| **기본 흐름**    | 1. 관리자가 본인의 상담 접수 상세 화면을 조회한다.<br>2. 시스템은 실제로 존재하는 녹음 원본 접근 수단·STT 원문·AI 원본 JSON 필드와 현재 편집값을 구분하여 제공한다. 녹음은 상세의 recordingFileId로 녹음 접근 API를 호출하여 단기 재생 URL을 받는다. 최초 AI 결과가 유효하게 반영되었고 관리자 저장값이 없으면 추출값으로 편집 초깃값을 자동 채운다. 이미 저장된 관리자 값은 유지한다. 분석 중이면 진행 상태를 표시하고 완료 푸시 수신 후 결과를 조회한다. 분석 중에는 입력·수정·검토 완료를 잠그고, 처리 종료 후 성공값 검토 또는 실패 시 E1 수동 보완으로 진행한다.<br>3. 분석이 종료되면 관리자가 자동 채워진 작업 유형, 증상, 주소, 정확한 방문 시작·종료 시각과 연락처를 확인·보완한다. 고객 부가정보는 선택적으로 확인·보완한다.<br>4. 관리자가 화면에서 필요한 정보를 수정한다. 별도의 임시 저장 요청은 보내지 않으며 녹음·STT·AI 원본은 수정하지 않는다.<br>5. 관리자가 검토 완료를 선택하면 앱이 전체 최종값과 조회한 버전을 한 요청으로 보낸다.<br>6. 시스템은 분석 종료 여부·필수값·방문 구간·소유권·버전·현재 상태를 검증하고 수정값 저장과 검토 확정을 원자적으로 처리한다. 실패하면 기존 값과 상태를 유지한다. |
| **예외 흐름**    | E1. 상담 녹음 파일 확보, STT 처리, 원문 DB 저장 또는 AI 분석에 실패한 경우 → 시스템이 실패 상태를 표시하고 관리자가 접수 정보를 수동 입력한 뒤 기본 흐름 5~6의 검토 완료 및 최종 확정 저장 절차를 진행한다. 필수 접수 정보가 누락되면 E2에 따라 보완한 후 확정한다.<br>E2. 필수 접수 정보가 누락된 경우 → 시스템이 누락 항목을 안내하고, 해당 정보가 보완되기 전까지 최종 확정 저장을 제한한다. |
| **대안 흐름**    | A1. AI 추출값이 모두 정확하고 연락처를 포함한 필수 정보도 갖춰진 경우 → 관리자는 별도 수정 없이 현재 전체값으로 검토를 완료한다.<br>A2. 검토를 확정했지만 아직 의뢰로 등록하지 않은 경우 → 관리자가 확정을 취소하고 화면에서 수정한 뒤 검토 완료 요청으로 수정값 저장과 재확정을 함께 처리한다. 의뢰 등록 이후에는 접수 수정과 확정 취소를 제한한다. |
| **사후 조건**    | 관리자에 의해 확인된 접수 정보가 저장되며 의뢰 등록에 사용할 수 있다.                                                                                                                                                                       |

확정 필수값과 수정 가능 시점의 업무 기준은 [BR-04](../../../apps/backend/docs/business-specification.md#br-04)를 따른다.
현재 AI 추출 결과에는 연락처가 없으며, 자동 확보 방법은 프런트 검토 과제로 남긴다.
MVP에서는 재분석을 제공하지 않으며 실패·누락·오추출은 수동 입력·수정으로 보완한다.
고객의 부가 요청·전달사항은 선택 항목 `notes`로 확인·보완하여 최종 접수 정보와 의뢰에 함께 보존한다.
분석 결과 검토에서 `notes`도 다른 필드처럼 직접 추가·수정할 수 있다. AI 원본과 최신 관리자 편집값만 보관하고 중간 편집 이력은 남기지 않는다.
방문 텍스트 필드는 제공하지 않는다. 정확한 시작·종료 시각 중 하나라도 없으면 확정·의뢰 등록을 제한하고 관리자 보완을 안내한다.
필수값을 지운 상태의 관리자 저장은 허용하지 않는다. 관리자 수정은 검토 완료 시에만 서버에 반영한다.
빈 STT 결과는 '전사 내용 없음' 실패로 표시하고 구조화를 생략한다. 녹음 원본을 확인하며 수동 입력한 전체값으로 동일한 검토 완료 절차를 수행할 수 있다.
검토 완료에서 방문 종료가 서버 현재 시각 이후인지 확인한다. 현재 15시라면 14~16시 구간은 허용하고 13~14시 구간은 거부한다. 종료가 현재와 같은 구간도 거부한다.

AI 분석 종료 전 결과 조회는 읽기 전용이다. 분석 시도가 대기·진행 중이면 서버도 검토 완료를 거부한다.
