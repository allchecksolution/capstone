# UC-13 작업 보고서 등록

| 항목           | 내용                                                                                                                                                                                                                                  |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 기사                                                                                                                                                                                                                                  |
| **유스케이스 내용** | 기사가 수행한 작업의 내용과 결과를 작업 보고서로 등록한다.                                                                                                                                                                                                   |
| **사전 조건**    | 1. 기사가 로그인되어 있어야 한다.<br>2. 해당 기사가 작업의 유효한 담당자여야 하며, 작업이 보고서 제출이 허용되는 상태여야 한다. |
| **기본 흐름**    | 1. 기사가 작업 보고서 작성 화면에 진입한다.<br>2. 기사가 작업 전·후 사진을 등록한다.<br>3. 기사가 작업 내용, 진단 결과, 작업 비용 등 필요한 정보를 입력한다.<br>4. 기사가 작업 보고서를 제출한다.<br>5. 시스템이 입력된 정보와 제출 시점의 유효 담당자·작업 상태·제출 권한을 확인한다.<br>6. 시스템이 동일한 제출 요청의 반복 여부를 확인하여 보고서를 중복 생성하지 않고 해당 의뢰에 연결하여 저장한다.<br>7. 등록된 작업 보고서를 관리자가 조회할 수 있는 상태로 변경한다. |
| **예외 흐름**    | E1. 필수 항목이 누락된 경우 → 시스템이 누락된 정보를 안내한다.<br>E2. 사진 등록에 실패한 경우 → 시스템이 재등록을 요청한다.<br>E3. 보고서 저장에 실패한 경우 → 시스템이 오류를 안내한다.<br>E4. 작업이 취소되었거나 다른 기사에게 재배차되어 제출 권한이 없거나, 보고서 제출이 허용되지 않는 작업 상태인 경우 → 시스템이 제출을 거부하고 사유를 안내한다. |
| **대안 흐름**    | A1. 임시 저장 기능을 제공하는 경우 → 기사가 작성 중인 보고서를 임시 저장하고 이후 작성을 계속한다.                                                                                                                                                                         |
| **사후 조건**    | 작업 보고서가 해당 의뢰 및 작업 이력에 저장되고 관리자가 조회할 수 있다.<br>최초 제출 원본(작업 전·후 사진 포함)은 [FR-11](../functional-requirements/fr-11-work-report-registration-and-management.md)에 따라 보존하고 관리자 수정은 별도 이력으로 기록한다. 원본·수정 이력·첨부 파일의 접근 통제 및 보존·파기는 [UC-16](./uc-16-driver-account-withdrawal.md)을 따른다. |
| **설계 시 고려사항** | 정확한 보고서 제출 가능 상태, 임시 저장 제공 여부, 재제출 정책 및 중복 요청 식별 방식은 추후 결정한다. |
