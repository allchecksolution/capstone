# UC-03 의뢰 등록 및 배차 요청

| 항목           | 내용                                                                                                                                                                                                                                                                                       |
|--------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 관리자                                                                                                                                                                                                                                                                                      |
| **유스케이스 내용** | 관리자가 검토한 상담 접수 정보를 의뢰로 확정하고 시스템이 출동 가능한 기사에게 배차 요청을 전달한다.                                                                                                                                                                                                                                |
| **사전 조건**    | 1. 관리자가 로그인되어 있어야 한다.<br>2. 접수에 필요한 정보에 대한 관리자 검토가 완료되어 있어야 한다.                                                                                                                                                                                                                          |
| **기본 흐름**    | 1. 관리자가 최종 접수 정보를 확인한다.<br>2. 관리자가 의뢰 등록을 선택한다.<br>3. 시스템이 의뢰를 생성한다.<br>4. 시스템이 [FR-05](../functional-requirements/fr-05-request-registration-and-dispatch-candidate-selection.md)에 따라 활성 계정인 기사 중 작업 유형, 작업 가능 상태, 전문 분야(외벽누수, 내벽누수, 막힘), 활동 지역, 유효한 최신 위치정보 및 진행 중 작업 여부 등의 조건을 만족하는 후보를 선별한다. 유효하지 않은 위치정보는 거리 기반 후보 선정에 사용하지 않는다.<br>5. 시스템이 선별된 기사에게 배차 요청을 전달한다.<br>6. 배차 요청이 정상적으로 전달된 기사에 대해 배차 절차를 진행하고 전달 결과에 따라 의뢰의 상태를 관리한다. 푸시 발행 또는 전달 서비스의 접수 성공을 기사의 실제 수신·확인 성공과 동일하게 취급하지 않는다. |
| **예외 흐름**    | E1. 필수 접수 정보가 누락된 경우 → 시스템이 의뢰 등록을 제한하고 누락 정보를 안내한다.<br>E2. 설정된 탐색 종료 조건에 도달할 때까지 적합한 기사 후보를 찾지 못한 경우 → 시스템은 탐색을 종료하고 정상적인 배차 진행과 구분하여 관리자에게 배차 가능한 기사가 없고 후속 배차가 필요함을 안내한다. 관리자는 대안 흐름 A1에 따라 후속 배차를 진행한다.<br>E3. 선정된 모든 기사에 대한 배차 요청 전달이 실패한 경우 → 시스템이 전달 실패 결과를 기록하고 관리자에게 안내하며, 요청이 정상적으로 전달된 경우와 구분한다.<br>E4. 일부 기사에 대한 배차 요청 전달만 실패한 경우 → 시스템이 기사별 전달 결과를 기록하고, 정상적으로 요청이 전달된 기사에 대한 배차 절차는 유지한다. 일부 전달 실패만으로 의뢰 전체를 배차 실패 처리하지 않는다. |
| **대안 흐름**    | A1. 자동으로 적합한 기사 후보를 확보하지 못한 경우 → 관리자가 상황을 확인하고 후속 배차를 진행한다.<br>A2. 초기 탐색 범위에서 적합한 기사 후보가 없는 경우 → 시스템은 설정된 배차 정책에 따라 탐색 범위를 확대하여 후보를 다시 탐색한다. |
| **사후 조건**    | 의뢰가 등록되고, 요청이 정상적으로 전달된 기사에 대한 배차 절차가 진행된다. 후보 미확보 및 전체 전달 실패는 정상적인 배차 진행과 구분하여 기록·안내하고, 일부 전달 실패는 기사별 전달 결과와 함께 관리한다. 상태 관리 및 조회는 [FR-09](../functional-requirements/fr-09-request-and-work-status-management.md) 및 [UC-04](./uc-04-dispatch-status-inquiry.md)와 일치시킨다. |
| **설계 시 고려사항** | 초기 탐색 반경, 확대 단위, 최대 반경, 타임아웃 및 탐색 종료 조건의 구체적인 수치는 추후 결정한다. 후보 미확보·전체 전달 실패·일부 전달 실패를 구분하는 상세 상태 명칭과 상태 전이, 자동 재시도 여부·조건·횟수는 추후 설계한다. 재처리 시 중복 배차 요청 및 중복 배정이 발생하지 않도록 정책을 설계해야 한다. |
