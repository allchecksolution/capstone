# UC-03 의뢰 등록 및 배차 요청

방문 종료가 미래인지 여부는 접수 검토 완료 때만 검사한다. 이후 의뢰 등록 시 종료가 지났더라도 등록을 허용하고 확정된 접수 스냅샷을 사용한다.
소유권·검토 확정 상태·버전 검증은 계속 적용하며, 상세 기준은 [BR-04](../../../apps/backend/docs/business-specification.md#br-04)를 따른다.

| 항목           | 내용                                                                                                                                                                                                                                                                                       |
|--------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 관리자                                                                                                                                                                                                                                                                                      |
| **유스케이스 내용** | 관리자가 검토한 상담 접수 정보를 의뢰로 확정하고 시스템이 출동 가능한 기사에게 배차 요청을 전달한다.                                                                                                                                                                                                                                |
| **사전 조건**    | 1. 관리자가 로그인되어 있어야 한다.<br>2. 접수에 필요한 정보에 대한 관리자 검토가 완료되어 있어야 한다.                                                                                                                                                                                                                          |
| **기본 흐름**    | 1. 관리자가 최종 접수 정보를 확인한다.<br>2. 관리자가 의뢰 등록을 선택한다.<br>3. 시스템이 확정 주소로 현장 좌표를 확보하고 의뢰를 생성한다. 좌표를 확정하지 못하면 의뢰와 배차를 생성하지 않는다.<br>4. 시스템이 [FR-05](../functional-requirements/fr-05-request-registration-and-dispatch-candidate-selection.md)에 따라 활성 계정인 기사 중 작업 유형, 작업 가능 상태, 전문 분야(막힘, 외벽 누수, 내벽 누수, 보일러, 방수), 활동 지역, 유효한 최신 위치정보 및 진행 중 작업 여부 등의 조건을 만족하는 후보를 선별한다. 유효하지 않은 위치정보는 거리 기반 후보 선정에 사용하지 않는다.<br>5. 시스템이 선별된 기사에게 배차 요청을 전달한다.<br>6. 배차 요청이 정상적으로 전달된 기사에 대해 배차 절차를 진행하고 전달 결과에 따라 의뢰의 상태를 관리한다. 푸시 발행 또는 전달 서비스의 접수 성공을 기사의 실제 수신·확인 성공과 동일하게 취급하지 않는다. |
| **예외 흐름**    | E1. 주소 미일치·복수 후보 미해결 또는 제공자 장애로 현장 좌표를 확보하지 못한 경우 → 시스템은 의뢰·배차를 생성하지 않고 접수 확정 상태를 유지하며 원인을 안내한다. 주소 문제는 기존 접수의 확정을 취소하고 수정·재확정한 뒤 등록하며, 일시 장애는 같은 확정 접수로 등록을 다시 시도할 수 있다. 복수 후보 중 하나를 임의로 선택하지 않는다.<br>E2. 필수 접수 정보가 누락된 경우 → 시스템이 의뢰 등록을 제한하고 누락 정보를 안내한다.<br>E3. 설정된 탐색 종료 조건에 도달할 때까지 적합한 기사 후보를 찾지 못한 경우 → 시스템은 탐색을 종료하고 정상적인 배차 진행과 구분하여 관리자에게 배차 가능한 기사가 없고 후속 배차가 필요함을 안내한다. 관리자는 대안 흐름 A1에 따라 후속 배차를 진행한다.<br>E4. 선정된 모든 기사에 대한 배차 요청 전달이 실패한 경우 → 시스템이 전달 실패 결과를 기록하고 관리자에게 안내하며, 요청이 정상적으로 전달된 경우와 구분한다.<br>E5. 일부 기사에 대한 배차 요청 전달만 실패한 경우 → 시스템이 기사별 전달 결과를 기록하고, 정상적으로 요청이 전달된 기사에 대한 배차 절차는 유지한다. 일부 전달 실패만으로 의뢰 전체를 배차 실패 처리하지 않는다.<br>E6. 기사 정보 조회 등 후보 탐색 자체가 일시적으로 실패한 경우 → 동일 조건을 최초 포함 총 3회까지 시도하며 실패 후 5초·10초를 대기한다. 계속 실패하거나 영구 오류이면 회차를 SEARCH_FAILED, 의뢰를 FOLLOW_UP_REQUIRED로 함께 전환하고 관리자에게 알린다. 조회 오류를 후보 없음으로 처리하거나 탐색 반경을 확대하지 않는다. |
| **대안 흐름**    | A1. 자동으로 적합한 기사 후보를 확보하지 못한 경우 → 관리자가 상황을 확인하고 후속 배차를 진행한다.<br>A2. 초기 탐색 범위에서 적합한 기사 후보가 없는 경우 → 시스템은 설정된 배차 정책에 따라 탐색 범위를 확대하여 후보를 다시 탐색한다. |
| **사후 조건**    | 의뢰가 등록되고, 요청이 정상적으로 전달된 기사에 대한 배차 절차가 진행된다. 후보 미확보 및 전체 전달 실패는 정상적인 배차 진행과 구분하여 기록·안내하고, 일부 전달 실패는 기사별 전달 결과와 함께 관리한다. 상태 관리 및 조회는 [FR-09](../functional-requirements/fr-09-request-and-work-status-management.md) 및 [UC-04](./uc-04-dispatch-status-inquiry.md)와 일치시킨다. |
| **설계 시 고려사항** | 탐색 반경·확대 조건·배차 응답 기한과 기사별 전달 재시도는 [BR-04](../../../apps/backend/docs/business-specification.md#br-04), 회차 종료 분류는 [BR-01](../../../apps/backend/docs/business-specification.md#br-01)을 따른다. 작업자 실행 주기와 연동 타임아웃은 구현·운영 설정으로 구분한다. 재처리는 동일 회차·요청·배정을 중복 생성하지 않아야 한다. |
