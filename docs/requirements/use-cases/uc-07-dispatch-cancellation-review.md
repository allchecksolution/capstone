# UC-07 배차 취소 요청 검토 및 재배차

| 항목           | 내용                                                                                                                                                                                                                    |
|--------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 관리자                                                                                                                                                                                                                   |
| **유스케이스 내용** | 관리자가 기사 배정 해제 후 남아 있는 고객 의뢰에 대해 배차 취소 요청을 검토하고 재배차 또는 의뢰 자체 취소를 결정한다. |
| **사전 조건**    | 1. 관리자가 로그인되어 있어야 한다.<br>2. [UC-13](./uc-13-dispatch-cancellation-request.md)에 따라 배차 취소 요청이 정상 접수되어 해당 기사 배정이 이미 해제되어 있어야 한다. |
| **기본 흐름**    | 1. 관리자가 배차 취소 요청 목록을 조회한다.<br>2. 관리자가 취소 사유와 의뢰 정보를 확인한다. 시스템은 처리 시점의 최신 의뢰 상태 및 배차 상태와 동일 취소 요청의 처리 상태를 확인한다.<br>3. 관리자가 재배차를 진행하기로 결정한다.<br>4. 시스템이 동일 취소 요청에 대해 재배차 또는 의뢰 취소 중 하나의 결정만 확정되도록 관리자 처리를 원자적으로 수행하고, 기존 배차 및 취소 이력을 보존한 채 해당 의뢰의 재배차 절차를 시작한다. 여러 관리자가 동시에 처리해도 동일 요청을 중복 처리하지 않는다.<br>5. 시스템이 [UC-03](./uc-03-dispatch-request.md)에 따라 출동 가능한 기사 후보를 다시 선별하여 배차 요청을 전달한다.<br>6. 관리자가 재배차 진행 상태를 확인한다. |
| **예외 흐름**    | E1. 재배차 가능한 기사 후보가 없는 경우 → 시스템이 관리자에게 안내하고 수동 처리를 요청한다.<br>E2. 이미 처리되었거나 다른 관리자가 처리 중인 요청인 경우 → 시스템이 중복 처리를 제한하고 현재 처리 상태를 안내한다.<br>E3. 처리 시점의 최신 의뢰 상태 또는 배차 상태가 관리자 결정과 충돌하는 경우 → 시스템이 충돌하는 결정을 확정하지 않고 현재 처리 상태를 안내한다. |
| **대안 흐름**    | A1. 관리자가 재배차 대신 의뢰 자체를 취소하기로 결정하는 경우 → 시스템이 최신 의뢰 상태 및 배차 상태와 취소 요청의 처리 상태를 확인하고, 기본 흐름과 동일한 원자성·중복 처리 방지 원칙에 따라 의뢰 취소 결정만 확정한다. 이미 해제된 기사 배정에 대한 승인·거부가 아닌 의뢰의 후속 처리이며, 의뢰를 취소 상태로 종료하고 기존 배차·취소 이력을 보존한다. |
| **사후 조건**    | 기사 배정은 취소 요청 정상 접수 시 이미 해제되어 있으며, 관리자 처리는 남아 있는 고객 의뢰의 후속 처리이다. 재배차 결정 후에는 새로운 배차 절차가 진행되고, 의뢰 취소 결정 후에는 의뢰가 취소 상태로 종료된다. 취소 요청의 처리 상태와 의뢰 자체의 상태는 구분한다. 재배차와 의뢰 취소가 동시에 확정되지 않으며, 기존 배차 및 취소 이력은 보존되고 동일 요청은 중복 처리되지 않는다. |
| **설계 시 고려사항** | 관리자 처리의 원자성 보장 방식, 충돌 해결 구현 및 상세 상태 명칭·전이 규칙은 추후 설계한다. |
