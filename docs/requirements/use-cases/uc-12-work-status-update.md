# UC-12 작업 진행 상태 변경

| 항목           | 내용                                                                                                                                                                                           |
|--------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 기사                                                                                                                                                                                           |
| **유스케이스 내용** | 배정된 기사가 실제 작업 진행 상황에 따라 작업 상태를 변경한다.                                                                                                                                                         |
| **사전 조건**    | 1. 기사가 로그인되어 있어야 한다.<br>2. 기사에게 배정된 유효한 의뢰가 존재해야 한다.                                                                                                                                         |
| **기본 흐름**    | 1. 기사가 배정된 의뢰를 조회한다.<br>2. 현장 작업을 시작하면서 `작업 시작`을 선택한다.<br>3. 시스템이 현재 상태에서 허용된 상태 전이인지 검증한 뒤 해당 의뢰의 작업 상태를 진행 중으로 변경한다.<br>4. 작업을 마친 후 기사가 `작업 완료`를 선택한다.<br>5. 시스템이 현재 상태에서 허용된 상태 전이인지 검증한 뒤 해당 의뢰의 작업 상태를 완료로 변경한다.<br>6. 변경된 상태가 관리자에게도 반영된다. |
| **예외 흐름**    | E1. 기사에게 배정되지 않은 의뢰의 상태 변경을 요청한 경우 → 시스템이 요청을 거부한다.<br>E2. 허용되지 않는 순서로 상태 변경을 요청한 경우 → 시스템이 변경을 제한한다.<br>E3. 상태 변경 처리에 실패한 경우 → 시스템이 오류를 안내한다.                                               |
| **대안 흐름**    | A1. 작업이 당일 완료되지 않고 추가 방문이 필요한 경우 → 시스템이 재방문이 필요한 상태로 처리한다.                                                                                                                                   |
| **사후 조건**    | 최신 작업 진행 상태가 저장되고 관리자와 기사에게 반영된다.                                                                                                                                                            |
