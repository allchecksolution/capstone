# UC-17 관리자·기사 1:1 채팅

| 항목           | 내용                                                                                                                                                                                            |
|--------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 관리자, 기사                                                                                                                                                                                       |
| **유스케이스 내용** | 관리자와 기사가 기사별 1:1 채팅을 통해 배차, 작업 및 현장 상황 등에 필요한 정보를 지속적으로 주고받는다.                                                                                                                                |
| **사전 조건**    | 1. 관리자 또는 기사가 로그인되어 있어야 한다.<br>2. 관리자와 해당 기사 사이에 채팅이 가능한 관계가 형성되어 있어야 한다.<br>3. 정상적인 채팅 이용 및 메시지 전송은 기사 계정이 '활성' 상태인 경우에만 허용한다. '승인 대기', '반려', '탈퇴' 기사의 일반 채팅 접근은 제한한다.<br>4. 권한 있는 관리자는 해당 기사가 탈퇴하거나 비활성화된 이후에도 [UC-16](./uc-16-driver-account-withdrawal.md)의 보존 정책에 따라 과거 대화를 읽기 전용으로 조회할 수 있다. 이 경우 새로운 메시지 전송은 허용하지 않는다. |
| **기본 흐름**    | 1. 관리자 또는 기사가 1:1 채팅 화면에 진입한다.<br>2. 시스템이 기존 대화 내역을 표시한다.<br>3. 사용자가 메시지를 입력하고 전송한다.<br>4. 시스템이 메시지 전송 시점의 기사 계정 상태와 채팅 권한을 확인하고, 동일한 전송 요청으로 메시지가 중복 저장되지 않도록 저장한다.<br>5. 시스템이 상대방에게 새로운 메시지를 전달한다.<br>6. 상대방이 메시지를 확인한다.<br>7. 관리자와 기사가 필요한 대화를 계속한다. |
| **예외 흐름**    | E1. 메시지 전송에 실패하거나 전송 결과를 확인할 수 없는 경우 → 시스템은 전송 상태를 안내하고 재전송을 허용한다. 동일한 메시지 전송 요청이 반복되더라도 메시지가 중복 저장되지 않도록 처리한다.<br>E2. 네트워크 연결이 불안정한 경우 → 시스템이 연결 상태 또는 메시지 전송 실패를 안내한다.<br>E3. 전송 시점에 기사 계정이 승인 대기·반려·탈퇴 상태이거나 채팅 권한이 없는 경우 → 시스템이 메시지 전송을 거부하고 사유를 안내한다. 비활성 기사의 일반 채팅 접근은 제한하되 권한 있는 관리자의 과거 이력 읽기 전용 조회는 허용한다. |
| **대안 흐름**    | A1. 상대방이 채팅 화면을 사용하고 있지 않은 경우 → 시스템이 새로운 메시지가 도착했음을 알림으로 전달한다.<br>A2. 권한 있는 관리자가 비활성 기사와의 과거 대화를 조회하는 경우 → 시스템은 보존 정책에 따라 대화 이력을 읽기 전용으로 제공하며 새로운 메시지 전송은 허용하지 않는다. |
| **사후 조건**    | 송수신된 메시지는 중복 없이 대화 이력으로 저장된다. 정상적인 채팅 이용은 활성 기사와의 대화에만 허용하며, 권한 있는 관리자는 비활성 기사와의 과거 이력을 읽기 전용으로 조회할 수 있다. 대화 이력의 접근 통제 및 보존·파기는 [UC-16](./uc-16-driver-account-withdrawal.md)의 개인정보 처리 정책을 따른다. |
| **설계 시 고려사항** | 메시지 고유 식별자 또는 멱등성 키 등을 활용한 구체적인 중복 요청 식별 방식은 추후 설계에서 결정한다. |
