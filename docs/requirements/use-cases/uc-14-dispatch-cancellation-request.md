# UC-14 배차 취소 요청

| 항목           | 내용                                                                                                                                                                                                    |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 기사                                                                                                                                                                                                    |
| **유스케이스 내용** | 배차를 수락한 기사가 불가피한 사유로 해당 작업을 수행할 수 없는 경우 배차 취소를 요청한다.                                                                                                                                                  |
| **사전 조건**    | 1. 기사가 로그인되어 있어야 한다.<br>2. 해당 기사가 의뢰를 수락하여 담당 기사로 배정되어 있어야 한다.                                                                                                                                        |
| **기본 흐름**    | 1. 기사가 배정된 의뢰를 조회한다.<br>2. 기사가 배차 취소 요청을 선택한다.<br>3. 시스템이 취소 사유 입력을 요청한다.<br>4. 기사가 취소 사유를 입력하고 요청을 제출한다.<br>5. 시스템이 해당 기사의 유효한 배정 여부와 취소 요청이 허용되는 상태인지 확인하고, 유효한 요청이면 취소 요청 접수와 기존 배정 해제를 원자적으로 처리한다. 동시 요청이 발생해도 동일 배정의 취소 접수와 배정 해제는 한 번만 성공해야 한다. 해당 기사는 정상 접수 즉시 배정에서 해제되고, 취소 요청과 사유는 관리자 후속 처리를 기다리는 것으로 기록한다. 이는 취소 요청의 처리 상태이며 의뢰 자체의 상태가 아니다.<br>6. 시스템이 관리자에게 배차 취소 상황을 표시한다.<br>7. 관리자는 [UC-07](./uc-07-dispatch-cancellation-review.md)에 따라 남아 있는 의뢰의 재배차 또는 의뢰 자체 취소를 결정한다. |
| **예외 흐름**    | E1. 유효한 배정이 없거나 취소 요청이 허용되지 않는 상태인 경우 → 시스템이 취소 요청을 제한한다.<br>E2. 취소 요청 처리에 실패한 경우 → 시스템이 오류를 안내하고, 취소 요청 접수와 배정 해제 중 일부만 반영되지 않도록 한다.<br>E3. 동일 배정에 대한 취소 요청이 이미 정상 처리된 경우 → 시스템이 기존 처리 결과를 반환하거나 중복 요청임을 안내한다. 새로운 취소 요청이나 관리자 후속 처리 요청을 중복 생성하지 않고 기존 배정 해제를 반복 실행하지 않는다. |
| **대안 흐름**    | A1. 취소 요청 전에 기사와 관리자가 [UC-17](./uc-17-admin-driver-chat.md)의 1:1 채팅을 통해 상황을 확인할 수 있다.                                                                                                                 |
| **사후 조건**    | 정상 접수된 취소 요청은 관리자 후속 처리를 기다리는 것으로 기록되고, 해당 기사의 기존 배정은 즉시 종료된다. 해제된 기사는 해당 의뢰의 작업 상태를 더 이상 변경할 수 없으며 다른 배차 요청을 수락할 수 있다. 고객 의뢰는 자동으로 취소되지 않으며, 관리자가 [UC-07](./uc-07-dispatch-cancellation-review.md)에 따라 재배차 또는 의뢰 자체 취소를 결정해야 한다. 기존 배차 및 취소 이력은 보존되고 동일 요청은 중복 처리되지 않는다. |
| **설계 시 고려사항** | 중복 요청 식별 방식, 취소 요청 접수와 배정 해제의 원자성 보장 방식, 취소가 허용되는 구체적인 작업 상태 및 상세 상태 명칭·전이 규칙은 추후 설계한다. |
