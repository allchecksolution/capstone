# UC-05 작업 보고서 검토 및 수정

| 항목           | 내용                                                                                                                                                                                        |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **행위자**      | 관리자                                                                                                                                                                                       |
| **유스케이스 내용** | 관리자가 기사가 제출한 작업 보고서와 작업 결과를 확인하고 필요한 경우 수정한다.                                                                                                                                             |
| **사전 조건**    | 1. 관리자가 로그인되어 있어야 한다.<br>2. 기사가 작업 보고서를 등록한 상태여야 한다.                                                                                                                                      |
| **기본 흐름**    | 1. 관리자가 작업 보고서 목록을 조회한다.<br>2. 관리자가 확인할 작업 보고서를 선택한다.<br>3. 시스템이 작업 전·후 사진, 작업 내용, 비용 등 보고서 정보를 표시하며, 최초 제출 원본과 전체 수정 이력을 추적할 수 있도록 제공한다.<br>4. 관리자가 작업 결과를 확인한다.<br>5. 필요한 경우 권한이 있는 관리자가 수정 가능한 정보를 수정한다.<br>6. 시스템은 최초 제출 원본(작업 전·후 사진 포함)을 덮어쓰지 않고 수정 항목, 수정 전 값, 수정 후 값, 수정자, 수정 시각을 원본과 별도의 수정 이력으로 누적 저장한다. 별도 승인 절차 없이 최신 유효 수정 내용을 보고서 조회와 작업 이력·통계에 반영한다. |
| **예외 흐름**    | E1. 작업 보고서가 아직 등록되지 않은 경우 → 시스템이 미등록 상태를 표시한다.<br>E2. 보고서 수정 또는 저장에 실패한 경우 → 시스템이 오류를 안내한다.<br>E3. 보고서 수정 권한이 없는 경우 → 시스템이 수정을 거부하고 사유를 안내한다. |
| **대안 흐름**    | A1. 수정할 내용이 없는 경우 → 관리자는 원본과 수정 이력을 조회만 수행하고 종료한다. |
| **사후 조건**    | 관리자가 작업 결과를 확인하며, 수정한 경우 원본과 별도의 수정 이력이 누적 저장되고 작업 이력 조회 및 통계에는 최신 유효 수정 내용이 반영된다. 원본과 전체 수정 이력은 추적 가능하며, 기사 탈퇴 시 원본·수정 이력·첨부 파일에도 [UC-16](./uc-16-driver-account-withdrawal.md)의 접근 통제 및 보존·파기 정책을 적용한다. |
